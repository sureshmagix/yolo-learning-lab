Module 01 • Fundamentals

What is YOLO? (You Only Look Once)

Traditional computer vision systems evaluated thousands of sliding windows or region proposals per image (R-CNN). YOLO frames object detection as a single regression problem: passing an image through the neural network just once to predict both bounding box locations and class probabilities simultaneously.

🏷️

1. Image Classification

Answers "What is inside this image?". Assigns a single categorical label to the entire picture. It does not locate where objects are.

Output: "Car" (98% conf)
🎯

2. Object Detection (YOLO)

Answers "What is it, and WHERE is it?". Predicts a rectangular bounding box with coordinates (x, y, w, h) plus class label.

Output: [plate: 0.50, 0.63, 0.18, 0.06]
🔤

3. Text OCR (ANPR)

Answers "What characters are written here?". Uses sequence recognition models to transcribe characters inside cropped license plates.

Output: "TN 09 AB 1234"
💡 Key Mental Model: YOLO detects where the license plate is. It does not read the alphanumeric text itself! Reading text requires an OCR model (like CRNN, PaddleOCR, or EasyOCR) running on the detected plate crop.
Module 02 • Coordinate Systems

Demystifying YOLO Bounding Box Math

Why does YOLO use fractions between 0.0 and 1.0 instead of pixel numbers? Cameras have varying resolutions (1080p, 4K, 720p). If annotations were in raw pixels, changing image resolution would break training. Normalization makes bounding boxes resolution-independent.

📐 The 5-Number YOLO Label Format

Every line in a YOLO annotation text file contains exactly 5 numbers separated by spaces:

class_id 0
x_center 0.500000
y_center 0.630000
width 0.180000
height 0.060000
Center X: cx = ((x1 + x2) / 2) / Image_Width
Center Y: cy = ((y1 + y2) / 2) / Image_Height
Box Width: w = (x2 - x1) / Image_Width
Box Height: h = (y2 - y1) / Image_Height
Notice: Origin (0,0) is always the top-left corner of the image. x increases to the right; y increases downwards.
🔄 Letterbox Preprocessing (Why Models Need Squares)

Most YOLO backbones require fixed square tensors (e.g., 640 × 640). To avoid stretching or distorting vehicles, the preprocessing pipeline applies aspect-preserving letterboxing with grey padding.

Input: 1000 × 500 Image → Target: 640 × 640
• Scale ratio: r = min(640/1000, 640/500) = 0.64
• Rescaled image: 640 × 320 px
• Vertical padding: (640 - 320) / 2 = 160 px (top & bottom)
• Point (500, 250) → Padded tensor (320, 320)
⚠️ Golden Rule: Always normalize annotations using the original image dimensions, not the letterboxed or padded tensor dimensions. YOLO loaders handle the transformation during training automatically.

Module 04 • Architectures

Model Landscape: Generations, Sizes & Tasks

When developers say "YOLO", they may refer to different generations, model scale factors, or computer vision tasks. Understanding these dimensions prevents mismatched architectures in production.

Architecture Family Core Innovation Anchor Mechanism Ideal Production Use Case
YOLOv5 / YOLOv7 Popularized accessible PyTorch training; ELAN architectures. Anchor-Based Legacy production edge devices with fixed ONNX kernels.
YOLOv8 / YOLO11 Anchor-free split head, C2f/C3k blocks, multi-task heads. Anchor-Free General CCTV surveillance, drone feeds, high accuracy.
YOLO26 End-to-end NMS-free heads, ultra-low latency inference. NMS-Free Anchorless Real-time highway toll cameras, embedded edge hardware.

Model Scale Variants

Nano (n) & Small (s): ~3M–11M parameters. Fits on Raspberry Pi, Jetson Nano, and mobile devices.

Medium (m) & Large (l): ~25M–45M parameters. Standard for workstation GPUs and cloud servers.

XLarge (x): Max mAP, compute-heavy. Best for offline high-resolution dataset re-labeling.

Task Variety

Detect: Standard rectangular bounding boxes.
Segment: Polygon masks outlining exact vehicle contours.
OBB (Oriented Box): Rotated bounding boxes for angled parking or aerial drone views.
Pose: Keypoints (e.g. 4 plate corner points for perspective rectification).

Edge Device Hardware Guide

• Raspberry Pi 5: YOLO11n exported to NCNN / ONNX (~18 FPS).
• NVIDIA Jetson Orin Nano: YOLO11s TensorRT FP16 (~65 FPS).
• Server RTX 4090: YOLO26m batch processing (~450+ FPS).

Module 05 • Training Process

From Labeled Images to Neural Weights

Training an accurate model requires structured dataset splitting, loss calculation, and iterative gradient descent.

📁 Ultralytics Dataset Structure 
dataset/
├── dataset.yaml
├── images/
│   ├── train/  # 70% of total frames
│   ├── val/    # 20% validation
│   └── test/   # 10% independent test
└── labels/
    ├── train/  # matching .txt files
    ├── val/
    └── test/
dataset.yaml (Plate Only)
path: /path/to/dataset
train: images/train
val: images/val
test: images/test
names:
  0: license_plate
⚠️ Avoid Video Data Leakage: Never randomly shuffle frames from the same video clip between train and val! Consecutive video frames are nearly identical, causing inflated validation scores that fail in the real world. Always split by distinct camera sessions or different days.
🎯 The 3 Primary Loss Functions

1. Box Loss (Complete IoU / CIoU)

Penalizes box error by measuring overlap area, distance between bounding box centers, and aspect ratio consistency.

2. Class Loss (Binary Cross-Entropy / BCE)

Measures classification confidence accuracy (whether a predicted box is truly a vehicle vs a license plate vs background).

3. DFL Loss (Distribution Focal Loss)

In anchor-free models (YOLOv8/11/26), boundary points are represented as probability distributions to handle blurred edges.

  batch=16 \

Module 06 • Temporal Association

Multi-Object Tracking & Tripwire Counting

A detection model operates on a single frame in isolation. Tracking connects detections across consecutive frames to maintain a persistent Track ID and prevent duplicate counting.

🧠 How ByteTrack & BoT-SORT Work

1. Kalman Filter Motion Estimation

Predicts where the vehicle will appear in the next video frame based on its prior velocity, position, and acceleration.

2. ByteTrack Association Trick

Traditional trackers discard low-confidence detections (<0.5). ByteTrack keeps them! If a low-confidence box matches a prior high-confidence track, it preserves the ID even through heavy rain, blur, or occlusion.

3. Directional Counting Logic

A tripwire line (x = 450) registers a count only when a vehicle's center point transitions from x < 450 to x >= 450. A cooldown registry prevents duplicate logs for the same ID. 

yolo track \
  source=traffic.mp4 \
  model=yolo26n.pt \
  tracker=bytetrack.yaml \
  show=True
