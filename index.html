01 / UNDERSTAND THE JOB

YOLO = You Only Look Once

YOLO is a family of neural networks for computer vision. A detection model processes an image and predicts object categories and bounding boxes in one forward pass. Think of it as a trained visual inspector: “a plate is here.” It does not automatically read the plate text.

Detection

Find each object in a frame.

class: plate
box: (400,250,600,350)
confidence: 0.92

Confidence is a model score, not a guaranteed probability of correctness.

Recognition / OCR

Read characters inside the cropped plate.

TN 09 AB 1234

Usually a separate text recognition model, or a custom character detection pipeline.

Tracking

Associate detections across video frames.

vehicle → track ID 17
frame 1 → 2 → 3

A temporary track ID is not a registration number or a permanent identity.

What does the network see?

A colour image is a grid of numerical pixel values: height × width × 3 colour channels. The loader resizes/pads it and prepares a tensor. Learned layers extract patterns such as edges, textures and vehicle/plate features at different scales; the prediction head estimates classes and boxes. Training adjusts millions of weights to reduce prediction error. Labels supervise learning; they are not supplied with a new image at inference.

The normalized box label is a training file convention. It is not the complete image representation inside the network. The original YOLO used a grid formulation; modern variants use different heads and feature scales, so a single fixed grid does not explain every YOLO model.

Normalization
cx = ((x1 + x2) / 2) / W
cy = ((y1 + y2) / 2) / H
w  = (x2 - x1) / W
h  = (y2 - y1) / H
Normalization describes position and size as fractions of the image. A width of 0.2 means 20% of the image width.
What happens when a 1000 × 500 image becomes 640 × 640?
With aspect-preserving letterboxing, scale r = 0.64. The content becomes 640 × 320, with 160 pixels padding above and below. Original (500,300) becomes (320,352). Mapping back requires subtracting the padding and dividing by r. Do not normalize original annotations by the padded input dimensions. The training loader transforms boxes with the image.


03 / ANNOTATION WORKFLOW
Every training image needs consistent ground truth
  1. Define the categories you want to detect.
  2. Draw a tight box around each visible target object.
  3. Assign its class ID using one shared class mapping.
  4. Normalize coordinates using the original image dimensions.
  5. Save one label row per object, paired with the image filename.
  6. Review labels before splitting and training.
Example: in a 1000 × 1000 image, box (400,250)–(600,350) has centre (500,300), width 200 and height 100. Class 0 produces 0 0.500 0.300 0.200 0.100. In a 1000 × 500 image, the same box produces 0 0.500 0.600 0.200 0.200.
Class IDs are dataset-specific. Use the same mapping for training, validation, testing and deployment.

Generation, size and task are different choices
FamilyHow to understand it

YOLOv4 / v5 / v7Different development branches, common in existing projects.
YOLOv8 / YOLO11Ultralytics families with detection and other task variants; many examples and existing deployments.
YOLOv6 / v9 / v10 / YOLO12Alternative research directions and architectures. Higher number alone does not prove better performance on your camera.
YOLO26Current documented Ultralytics starting point verified for this guide; supports end-to-end NMS-free detection. Benchmark against a supported YOLO11 baseline.
YOLO is an ecosystem, not a single company's sequential product line. This table is a representative map, not an exhaustive release inventory.
Size
n = nano, s = small, m = medium, l = large, x = extra-large in common Ultralytics families. Larger models generally require more compute and memory. Accuracy and speed must be measured on your data and hardware.
Task
Detect: rectangles. Segment: object masks. Classify: image category. Pose: keypoints. OBB: rotated boxes. These tasks need different labels; the five-number detection format is not universal.
Starting choice
Try nano/small detection for a first plate detector. Evaluate missed plates, false alarms, OCR accuracy and latency. Small distant plates may need better optics, higher resolution or a vehicle crop before plate detection.


05 / FROM EXAMPLES TO WEIGHTS
Training is repeated prediction and correction
  1. Collect representative images. Include front/rear plates, day/night, glare, blur, rain, angle and distance. Add backgrounds without plates. A few hundred images can start an experiment; there is no universal sufficient count.
  2. Annotate consistently. Draw a tight rectangle around the entire visible plate. Label all target objects under a consistent policy. OCR text needs separate transcription labels.
  3. Split by independent capture. For example, 70% train, 20% validation, 10% test. Keep neighbouring video frames and the same vehicle/session together to avoid leakage.
  4. Fine-tune a pretrained model. The model predicts; a loss measures box/class errors; backpropagation computes gradients; an optimizer updates weights. A batch is a subset of images; an epoch is a pass through the training set.
  5. Validate during development. Tune with validation data. Falling training loss with worsening validation suggests overfitting. Keep the test set untouched until final evaluation.
  6. Evaluate and deploy. Measure precision, recall, mAP, missed plates and latency. Separately test exact full-plate OCR accuracy, tracking ID switches, duplicate counts and real camera conditions.

Precision
Of predicted plates, how many were correct? Low precision means too many false alarms.
Recall
Of actual plates, how many were found? Low recall means missed plates.
IoU / mAP
IoU is overlap area divided by union area. mAP summarizes precision-recall performance under stated matching thresholds. It is not OCR accuracy.

A moving box needs an identity
Detection + association = tracking

Occlusion, similar cars, low frame rate and camera movement can cause ID switches. Track a vehicle and associate its plate crop with that vehicle; combine several sharp OCR readings for a more stable result.

Common beginner mistakes
  • Dividing y coordinates by image width instead of height.
  • Putting confidence or OCR text in a five-column training label.
  • Using different class IDs across train and validation.
  • Training on one camera and assuming all cameras will work equally well.
  • Resizing or cropping images without transforming annotations.
  • Assuming a good detection mAP guarantees readable plate text.
